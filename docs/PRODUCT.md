## 1. One-line pitch

Wingman is a personal agent that briefs you before every meeting: who you're meeting, what you last discussed, what you promised them, and what has changed in their world since — then emails you the dossier and drafts your follow-up.

## 2. The problem

- You walk into meetings cold.
- The context you need is scattered across old email threads, meeting notes, and docs.
- The public context (their company's news, their new role, their latest launch) lives on the web and changes daily.
- Nobody has 20 minutes before every meeting to stitch those two worlds together.
- The result: forgotten promises, repeated questions, and missed openings.

## 3. Target user

- **Primary:** A working professional with 3+ external meetings per week.
- **Examples:**
  - Founder meeting investors and customers.
  - Engineer or PM meeting vendors, partners, and candidates.
  - Job seeker meeting recruiters and hiring managers.
  - Sales or customer-success rep meeting accounts.
- **Hackathon persona:** "Karan, a developer who has a coffee chat tomorrow with someone he emailed three months ago and barely remembers."

## 4. What Wingman does (user journey)

1. Wingman reads tomorrow's calendar.
2. For each external meeting, it identifies the attendees.
3. It asks the **Personal Brain** (Cognee): "What do I know about this person and their company?"
4. It asks the **live web** (Bright Data): "What is publicly new about this person and their company?"
5. It reconciles the two and flags anything in your memory that is now out of date.
6. It renders a one-page dossier PDF with an interaction timeline (generated by code run in a Docker sandbox).
7. It takes action:
   - Emails you the dossier.
   - Adds talking points to the calendar event.
   - Drafts a "here's what I owe you" follow-up message.
8. It writes what it learned back into the brain, so the next dossier is better.

## 5. The dossier (the core artifact)

Each dossier is one page with these sections:

- **Who:** Name, role, company, how you know them.
- **Last time:** Date and summary of your last interaction.
- **Open commitments — you owe them:** Things you promised and have not delivered.
- **Open commitments — they owe you:** Things they promised you.
- **What changed since you last spoke:** Fresh public facts, each with a source link.
- **Stale memory alerts:** Facts in your brain that the web now contradicts (for example, "your notes say she is at Stripe; LinkedIn says she joined Ramp in August").
- **Talking points:** Three suggested openers that connect your history to their news.
- **Timeline chart:** A small visual of every interaction over time.

## 6. Feature scope

### P0 — must work for the demo

- Ingest a folder of emails, meeting notes, and a calendar file into Cognee.
- Parse the calendar and pick the next external meeting.
- Recall person and company context from the brain.
- Search and scrape fresh public info via Bright Data.
- Generate the dossier (Markdown first, then PDF via the sandbox).
- Email the dossier to yourself.

### P1 — strong differentiators, build if on schedule

- "What changed since you last spoke" diff with stale-memory alerts.
- Interaction timeline chart rendered by sandboxed code.
- Draft follow-up email covering open commitments.
- Write new learnings back into the brain after each run.

### P2 — stretch

- Patch talking points into the Google Calendar event description.
- Live Gmail and Google Drive connectors instead of an exported folder.
- LinkedIn structured profile data via Bright Data's `social` tool group.
- A daily scheduled run at 7:00 AM.

### Explicit non-goals for today

- No multi-user support.
- No web UI beyond what is needed for the demo (CLI plus the PDF is enough).
- No auto-sending emails to other people — drafts only.
- No fine-grained permissions model.

## 7. How each sponsor technology earns its place

- **Cognee — The Brain:**
  - Turns emails and notes into a knowledge graph of people, companies, topics, and commitments.
  - Enables multi-hop questions a vector store cannot answer, such as "what did I promise anyone at this person's company?"
- **Bright Data — The Web:**
  - Supplies the live public half of the dossier.
  - Powers the stale-memory check.
- **AWS Strands Agents — The Harness:**
  - Orchestrates the loop: calendar → brain → web → reconcile → render → act.
  - Decides which tools to call and when it has enough information.
- **Docker Sandbox — The Safe Hands:**
  - Runs the agent-written Python that builds the timeline chart and the PDF.
  - Keeps LLM-generated code away from the host machine and the network.
- **Your Data — The Personal Brain:**
  - A local folder of exported emails, notes, and a calendar file.

## 8. Demo script (3 minutes)

1. **Hook (20 s):** "I have a meeting tomorrow with someone I last emailed three months ago. I remember nothing. Watch."
2. **Show the brain (30 s):** Open the Cognee graph visualization and point at the person → company → commitment path.
3. **Run Wingman (60 s):** One command. Narrate the tool calls as they stream: brain recall, web search, scrape, sandbox render.
4. **Reveal the dossier (40 s):** Open the PDF. Highlight the stale-memory alert and the open commitment.
5. **Show the action (20 s):** The email arriving in the inbox, and the follow-up draft.
6. **Live twist (30 s):** Add a judge or sponsor as a meeting attendee and regenerate on stage using public data only.
7. **Close (10 s):** "My brain remembers, checks itself against the world, and does the prep for me."

### Demo safety rules

- Use curated or lightly faked personal data — the inbox will be on a projector.
- Pre-cache one complete successful run as a fallback in case Wi-Fi fails.
- For the live twist, only use public, professional information about the volunteer, and ask them first.

## 9. Judging criteria mapping

- **"Will it remember better?"** → Graph memory with commitments, plus write-back after every run.
- **"Find better information?"** → Bright Data search and scrape with source links on every fact.
- **"Reason across personal and public data?"** → The stale-memory diff is exactly this.
- **"Can it take useful actions?"** → Email sent, follow-up drafted, calendar updated.
- **"Not just another chatbot."** → There is no chat box; it runs from your calendar and produces a deliverable.

## 10. Success metrics for the demo

- End-to-end run completes in under 90 seconds per meeting.
- Dossier contains at least one open commitment pulled from the brain.
- Dossier contains at least two fresh web facts with source links.
- At least one stale-memory alert is triggered on the seeded data.
- An email with the PDF attachment lands in the inbox live.

## 11. Risks and mitigations

- **Risk:** OAuth setup for Gmail or Calendar eats an hour.
  - **Mitigation:** Use an exported folder and SMTP with an app password; treat live connectors as P2.
- **Risk:** Cognee ingestion is slow on a large mailbox.
  - **Mitigation:** Ingest a small curated slice (20–40 documents) before the event starts.
- **Risk:** The web scrape returns noisy or wrong-person results.
  - **Mitigation:** Always search with name plus company, and require the agent to cite a URL for every web fact.
- **Risk:** Agent-written PDF code fails in the sandbox.
  - **Mitigation:** Ship a known-good render template; the agent only fills in data. Fall back to Markdown.
- **Risk:** Venue Wi-Fi is unreliable.
  - **Mitigation:** Cached fallback run and a pre-rendered PDF.
